# video-calls ownership

Repository: https://github.com/ourapps-ae/video-calls.git (local only; nothing pushed). Package `ourapps-ae/video-calls`, provides `facility` (`ae/media-session`), requires `configuration` (`ae/video-calls-configuration`). Manifest format 2.
Server room handlers belong to `realtime-rooms`; game-specific client rendering belongs to the recipe.

Code: `implementation/server/video.ts`, `implementation/web/video.ts`, `implementation/apple/Sources/VideoSession.swift`, `implementation/android/src/main/java/ae/video/VideoSession.kt`, and `implementation/verification/` (native, browser and provider runners).
Artefacts: `component.json`, `CONTRACT.md`, `INSTRUCTIONS.md`, `SOURCE.md`, `suitability.json` (LiveKit free, paid and scale profiles, limits cited from livekit.io/pricing and the LiveKit quotas page), `tools.lock.json`, `SOURCE.json`, `interfaces/contract.json` (OpenRPC 1.3.2 of the provided ae/media-session interface), `interfaces/media-session-verification.json` (OpenRPC 1.3.2 of the verification helpers), `interfaces/required-configuration.json` (JSON Schema 2020-12), `tests/native/dependencies.json` (native locks), `tests/`, `visual/`. No data is kept (provider rooms are ephemeral), so there is no `migration.json`.
Platform checks: `scripts/platform-check.py` runs the Apple build, Apple media test, Android media and cleanup against `tests/native/`, locked by `tests/native/apple/Package.resolved` and `tests/native/android/gradle/verification-metadata.xml`. Known limits: apple-media fails under a tool selection because the `xcrun` directory shadows the selected `xcodebuild`, and the television x86_64 option in `scripts/check-apple.py` cannot link. Provider-media never ran (no authorised provider).
